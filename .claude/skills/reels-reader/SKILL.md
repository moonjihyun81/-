# 릴스 읽어주기

사용자는 비개발자일 수 있다. 한국어로, 짧게, 명령은 복사해서 쓸 수 있게 안내한다.
기계적인 작업(다운로드·받아쓰기·장면 사진)은 `scripts/read_reel.py`가 하고, 클로드는 사진을 직접 보고 정리한다.

## 0. 처음 한 번: 설치 점검

먼저 확인한다: `yt-dlp --version`, `ffmpeg -version`, `python3 -c "import faster_whisper"`.
이미 있는 건 건너뛰고, 없는 것만 설치한다. 허락 창이 뜨면 사용자가 내용을 보고 허용하면 된다고 알려준다.

| 프로그램 | 하는 일 | 설치 |
| --- | --- | --- |
| yt-dlp | 영상 받기 | `pip install -U yt-dlp` (맥은 `brew install yt-dlp`도 가능) |
| ffmpeg | 화면 사진 뽑기 | 맥 `brew install ffmpeg` · 윈도우 `winget install Gyan.FFmpeg` · 리눅스 `sudo apt install ffmpeg` |
| faster-whisper | 받아쓰기 | `pip install -U faster-whisper` |

- 첫 받아쓰기 때 음성 모델(기본 `small`, 약 500MB)을 한 번 내려받는다. 처음엔 시간이 걸린다고 미리 말해준다.
- yt-dlp는 인스타가 자주 바뀌어서 오래되면 막힌다. 다운로드가 이상하면 제일 먼저 `pip install -U yt-dlp`.

## 1. 실행

```bash
python3 <이 스킬 폴더>/scripts/read_reel.py "<링크>" --out reels/<짧은이름>
```

- `<짧은이름>`은 링크의 릴스 ID(`/reel/ABC123/`의 `ABC123`)를 쓴다. 여러 개를 읽어 나중에 비교할 수 있게 겹치지 않게 저장한다.
- 링크 대신 내 컴퓨터의 영상 파일 경로를 줘도 된다 (내가 찍은 릴스 점검용).
- 옵션: `--model medium`(더 정확·더 느림), `--lang en`(영어 릴스), `--threshold 0.2`(장면을 더 잘게), `--max-frames 30`.
- 결과물: `scenes.json`(장면별 시작·끝 시간, 사진 경로, 그 구간의 말), `transcript.json`, `info.json`(제목·계정·설명), `frames/*.jpg`.

## 2. 사진 보고 정리

1. `scenes.json`을 읽는다. `info.description`(캡션)도 참고한다.
2. `frames/`의 사진을 **Read로 한 장씩 직접 본다**. 짐작으로 쓰지 않는다. 화면 글자(자막·제목)는 그대로 옮기고, 인물·물건·구도·화면 전환을 짧게 적는다.
3. 아래 형식으로 답한다.

```
## 원본 요약
- (3줄, 한 줄에 한 가지)

## 장면별 내용
| 시간 | 화면 | 말 |
| --- | --- | --- |
| 0:00–0:02 | (사진에서 본 것 + 화면 글자) | (그 구간 받아쓰기, 없으면 "—") |

## 내 분야에 바꿔 쓸 아이디어 3개 (내 분야: OO)
1. ...
```

- **내 분야**: 사용자가 말해준 적이 없으면 처음 한 번 물어보고, 대답을 이 대화 동안 기억해서 다음 릴스부터 다시 묻지 않는다. 사용자가 원하면 이 파일의 이 줄에 적어둬도 된다.
- 받아쓰기가 틀려 보이면(고유명사 등) 화면 자막을 근거로 고쳐 쓰고, 고쳤다고 표시한다.
- 말이 없는 영상(음악만)은 "말 없음, 음악/효과음"으로 적고 화면 글자 중심으로 정리한다.

## 3. 막혔을 때

| 메시지 | 뜻 | 사용자에게 안내 |
| --- | --- | --- |
| `LOGIN_REQUIRED` (종료코드 2) | 인스타가 로그인 없이는 안 보여줌 | 아래 "로그인 막힘" 순서 |
| `TRANSCRIBE_FAILED` | 음성 모델을 못 받음(인터넷·용량) | 와이파이 확인 후 다시. 장면 사진은 이미 나왔으니 화면만으로 먼저 정리해준다 |
| `ffmpeg 가 설치돼 있지 않아요` | 설치 누락 | 0번 표대로 설치 |
| Unsupported URL / 비공개 계정 | 링크 형식 문제 또는 비공개 | 공개 릴스 링크인지, `instagram.com/reel/...` 형태인지 확인 |

**로그인 막힘** — 쉬운 순서대로:
1. 평소 쓰는 브라우저(크롬·사파리·엣지)에서 인스타에 로그인돼 있는지 확인한다.
2. `--browser chrome`(또는 `safari`, `edge`, `firefox`)을 붙여 다시 실행한다. 브라우저의 로그인 정보를 잠깐 빌려 쓰는 방식이라 파일이 따로 생기지 않는다. 맥에서 사파리는 "전체 디스크 접근" 허용이 필요할 수 있다.
3. 그래도 안 되면 브라우저 확장 프로그램 "Get cookies.txt LOCALLY"로 인스타 탭의 `cookies.txt`를 내보내고 `--cookies cookies.txt`로 실행한다.

## 4. 이렇게도 쓴다

- **내 릴스 점검**: 내가 올린 릴스를 넣으면 **첫 3초**의 화면과 말을 따로 뽑아, 멈추게 하는 힘(훅)이 있는지 짧게 평가한다.
- **잘되는 계정 구조 뽑기**: 여러 개를 읽은 뒤 "지금까지 읽은 릴스 N개의 공통 구조 정리해줘"라고 하면, `reels/*/scenes.json`을 모두 읽어 **첫 3초 / 중간 전개 / 마지막 CTA**로 나눠 공통점과 예시를 표로 정리한다.
- **여러 개 한꺼번에**: 링크를 여러 줄 주면 하나씩 차례로 돌리고, 각각 위 형식으로 정리한 뒤 마지막에 한 줄 비교를 붙인다.

## 5. 꼭 지킬 것

- **cookies.txt는 인스타 계정 열쇠다.** 사용자 컴퓨터에만 둔다. 깃 저장소에 커밋하거나, 채팅·메일·다른 서비스로 보내거나, 내용을 출력하지 않는다. 작업 폴더가 저장소 안이면 `.gitignore`에 `cookies.txt`와 `reels/`를 추가한다.
- **남의 릴스는 공부용으로만.** 요약하고 구조를 배우는 데까지만 돕는다. 영상이나 대본을 그대로 다시 올리는 용도의 전체 대본 복제·재업로드용 편집은 하지 않는다. 아이디어는 사용자 분야에 맞게 새로 바꿔 쓴다.
- 다 끝나면 `video.mp4`는 지워도 된다고 알려준다 (분석 결과는 `scenes.json`과 사진만 있으면 충분).
