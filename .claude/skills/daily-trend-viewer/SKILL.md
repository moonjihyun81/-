# 터지는 콘텐츠 수집 — 데일리 트렌드 뷰어 (AI Office 1단계)

사용자는 비개발자일 수 있다. 한국어로, 짧게, 명령은 복사해서 쓸 수 있게 안내한다.
목표는 하나: **"이번 주 내 분야에서 뭐가 터졌지?"를 아침 5분 안에 확인하기.**

- 원본: https://github.com/lmorejh/daily-trend-viewer (만든 분: lmorejh님)
- API 키 없음, 0원, 파이썬 표준 라이브러리만 사용(따로 `pip install` 할 것 없음)
- 기간(오늘·이번 주·이번 달) × 정렬(조회수·좋아요·댓글)을 화면에서 바로 바꿈

## ① 설치 없이 바로 보기 (웹 버전)

https://lmorejh.github.io/daily-trend-viewer/

- 1시간마다 자동으로 새 데이터가 모인다.
- 웹 버전에서는 **검색·새로고침·계정 추가/삭제·좋아요순 정렬이 꺼져 있다.**
- 인스타 등 일부 소스는 깃허브 서버를 막아서 비어 있을 수 있다. 전부 보려면 ②.

## ② 내 컴퓨터에서 켜기

1. 파이썬 설치: https://www.python.org/downloads/
   - 윈도우는 설치 첫 화면에서 **"Add Python to PATH"를 꼭 체크**.
   - 이미 있는지 확인: `python --version` (맥은 `python3 --version`)
2. 원본 깃허브에서 초록색 **Code → Download ZIP** → 압축 풀기.
3. 폴더 안 실행 파일 더블클릭
   - 윈도우: `실행-Windows.bat`
   - 맥: `실행-Mac.command` (경고가 뜨면 오른쪽 클릭 → 열기 → 열기)
4. 검은 창이 뜨고 브라우저가 자동으로 열린다. 안 열리면 주소창에 `http://localhost:8778`.
5. 끌 때는 그 검은 창만 닫으면 된다.

- 터미널로 직접: 폴더에서 `python3 server.py` (윈도우는 `python server.py`).
- 릴스·X·틱톡·스레드 탭에서 참고 계정을 화면에서 바로 추가·삭제할 수 있다.

## ③ 내 것으로 고치기 (Claude가 직접 작업)

사용자가 압축 푼 폴더를 Claude Code로 열었으면, 아래를 **클로드가 직접** 한다. 시작 전에 `README.md`와 관련 파일을 먼저 읽어 실제 구조를 확인하고, 추측으로 고치지 않는다.

### 파일 지도

| 파일 | 내용 |
| --- | --- |
| `server.py` | 로컬 서버(포트 8778)와 수집 함수. 유튜브·쇼츠 **카테고리와 검색 키워드**가 여기 있다 |
| `index.html` | 화면 전체(디자인·색·제목) |
| `reels_accounts.json` / `x_accounts.json` / `tiktok_accounts.json` / `threads_accounts.json` | 탭별 참고 계정 (화면에서 추가하면 여기 저장됨) |
| `collect.py` | 웹 버전용 수집·정적 사이트 생성 (`server.py` 함수 재사용) |
| `static_shim.js` | 웹 버전에서 `/api/*` 호출을 JSON 파일로 바꿔줌 |
| `.github/workflows/pages.yml` | 웹 버전 자동 수집·배포 일정 |
| `seed/`, `update_seed.py`, `시드갱신-릴스.bat` | 웹 버전 릴스용 시드 데이터(깃허브 서버가 막혀 집 PC에서 수집해 올림) |

### 3-1. 카테고리를 내 분야로

사용자에게 **내 분야**(예: AI 툴, 자기계발, 콘텐츠 제작)를 묻는다. 그다음:
1. `server.py`에서 유튜브·쇼츠 카테고리 정의를 찾는다. 화면 탭 이름이 `index.html`에도 따로 있으면 같이 맞춘다.
2. 카테고리마다 **검색 키워드 3~5개**를 넣는다. 한국어 키워드 위주, 너무 넓은 단어("AI")만 쓰지 말고 구체적인 것("챗GPT 활용", "AI 영상 만들기")을 섞는다.
3. `python3 server.py`를 다시 켜고 `curl` 또는 브라우저로 각 카테고리에 영상이 실제로 나오는지 확인한다. 비는 카테고리는 키워드를 바꿔 다시.
4. 무엇을 바꿨는지 표로 보여준다(카테고리 / 키워드).

### 3-2. 내가 보는 계정 넣기

- 사용자에게 매일 참고하는 계정 아이디를 한 줄에 하나씩 받는다. `@`와 주소(`instagram.com/...`)는 떼고 아이디만 넣는다.
- 기본 계정을 지울지 먼저 확인하고(가이드는 "지워줘"), 기존 JSON 형식 그대로 저장한다.
- **10개로 작게 시작**하라고 권한다. 많으면 느려지고 미러 사이트가 막을 수 있다.
- 다른 탭도 원하면 `x_accounts.json`, `tiktok_accounts.json`, `threads_accounts.json`에 같은 방식으로.

### 3-3. 화면을 내 브랜드 색으로

- `index.html`의 **디자인·레이아웃은 그대로 두고 색만** 바꾼다. 메인 색(예: `#E0668F`)을 받아 CSS 변수/색 값만 교체하고, 글자와 배경 대비가 충분한지 확인한다.
- 제목에 사용자 계정 이름(`@내계정`)을 넣는다.
- 바꾼 뒤 서버를 켜서 화면이 깨지지 않았는지 확인한다.

## ④ 매일 아침 7시에 알아서 모이게 (GitHub Actions + Pages)

사용자가 직접 할 일(클로드는 대신 못 함):
1. 깃허브 로그인 → 원본 저장소 오른쪽 위 **Fork** → 내 계정으로 가져오기.
2. 내 Fork에서 **Actions 탭 → "I understand my workflows, go ahead and enable them"** 눌러 켜기. (Fork는 처음에 Actions가 꺼져 있다.)
3. **Settings → Pages → Build and deployment → Source: GitHub Actions** 선택.

클로드가 할 일 (`.github/workflows/pages.yml`):
- 지금은 매시 23분에 돈다. **한국 시간 아침 7시 = UTC 전날 22시**라서 cron은 아래처럼 바꾼다.

```yaml
on:
  schedule:
    - cron: '0 22 * * *'   # 매일 07:00 KST (UTC+9)
  workflow_dispatch:        # 수동 실행 버튼(있으면 유지)
```

- 깃허브 예약 실행은 몇 분~수십 분 늦을 수 있다. 7시 전에 꼭 모여 있어야 하면 `'30 21 * * *'`(06:30 KST)를 권한다.
- 바꾼 뒤 Actions 탭에서 **Run workflow**로 한 번 수동 실행해 초록 체크가 뜨는지 확인하게 한다.
- 사이트 주소: `https://<내깃허브아이디>.github.io/daily-trend-viewer/` (저장소 이름을 바꿨으면 그 이름).

알아둘 것:
- 저장소에 **60일 동안 커밋이 없으면 깃허브가 예약 실행을 자동으로 멈춘다.** 멈추면 Actions 탭에서 다시 켜면 된다.
- 웹 버전 릴스는 `seed/` 데이터를 쓴다. 내 계정으로 바꾼 릴스를 웹에서도 보려면 집 PC에서 `시드갱신-릴스.bat`(윈도우)로 시드를 갱신해 푸시해야 한다. 안 그러면 원작자 계정 기준 시드가 남는다.
- 수집이 실패한 소스는 이전 스냅샷을 재사용하므로, 하루 비어도 데이터가 사라지진 않는다.

## 막혔을 때

| 증상 | 원인 | 안내 |
| --- | --- | --- |
| `python`을 찾을 수 없음 | PATH 미체크 | 파이썬 다시 설치하며 "Add Python to PATH" 체크 |
| 맥에서 "확인되지 않은 개발자" | 보안 경고 | 오른쪽 클릭 → 열기 → 열기 |
| 브라우저가 안 열림 | 자동 열기 실패 | `http://localhost:8778` 직접 입력 |
| 포트 사용 중 | 이미 켜져 있음 | 열려 있는 검은 창을 닫고 다시 실행 |
| 릴스 탭이 비어 있음 | 인스타·미러 차단, 계정 너무 많음 | 잠시 뒤 새로고침, 계정 10개 이하로 |
| 웹 버전 일부 탭 빈칸 | 깃허브 서버 IP 차단 | 정상. 전부 보려면 ② 로컬 실행 |
| Actions가 안 돎 | Fork라 꺼져 있음 / 60일 휴면 | Actions 탭에서 켜기 |
| Pages 404 | Source 설정 안 됨, 첫 배포 전 | Settings → Pages → GitHub Actions, 수동 실행 1회 |

## 오늘 당장 할 것 하나

웹 버전을 열고 **이번 주 · 조회수순**으로 바꿔서, 내 분야에서 제일 위에 있는 영상 3개만 캡처해 두라고 권한다. 그 3개가 다음 콘텐츠 기획의 출발점이다.
- `reels-reader` 스킬이 있으면 그 3개 링크를 넣어 "릴스 읽어줘"로 장면별 구조까지 뽑을 수 있다고 이어서 안내한다.
